# PostService

## Назначение

Сервис для работы с постами. Реализует создание, чтение, обновление и удаление постов с проверкой прав доступа. Учитывает приватность аккаунта при чтении постов. Управляет изображениями через MinIO. Метод `toSummary` преобразует сущность `Post` в DTO ответа.

## Полный разбор кода

### Основные методы

**`create`** — создаёт пост, загружает изображение, разрешает теги.

**`findById`** — находит пост и проверяет доступ (приватный аккаунт → только подписчики).

**`update`** — только автор может редактировать.

**`delete`** — автор или модератор/администратор.

**`findUserPosts`** — посты пользователя с cursor-пагинацией. Для приватных аккаунтов — только подписчики.

### Ключевые паттерны

**`@Transactional(readOnly = true)`**
Только для чтения — Hibernate не отслеживает изменения сущностей. Это оптимизация производительности.

**`boolean isModerator = currentUser.getRole() == UserRole.moderator || currentUser.getRole() == UserRole.admin`**
Модераторы и администраторы могут удалять любые посты. `==` для enum безопасен — enum использует ссылочное равенство, каждое значение существует в одном экземпляре.

**`resolveTags(request.tagNames(), request.tagIds())`**
Теги можно передавать двумя способами: по именам (создаёт если нет) или по ID. Метод объединяет оба варианта, ограничивая общее количество тегов до 10.

**`tagNames.stream().filter(n -> n != null && !n.isBlank()).limit(10).map(tagService::findOrCreate).forEach(tags::add)`**
Цепочка Stream:
1. `filter` — убирает пустые строки
2. `limit(10)` — не более 10 тегов
3. `map(tagService::findOrCreate)` — находит тег по имени или создаёт новый
4. `forEach(tags::add)` — добавляет в множество

**`tagIds.stream().limit(10 - tags.size())`**
Учитывает уже добавленные теги из `tagNames` — общий лимит 10.

**`checkReadAccess`**
Если автор поста — публичный: доступно всем. Если приватный: только сам + подписчики (`accepted`). Если нет доступа — `UnauthorizedException`.

**`toSummary(Post post, boolean liked, boolean saved)`**
Преобразует JPA-сущность в DTO. Принимает флаги `liked`/`saved` снаружи — они вычисляются в контроллере эффективным batch-запросом.
